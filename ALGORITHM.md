# Алгоритм работы репозитория

Этот проект строит интерактивный дашборд для анализа матчей WTA/ATP и включает два основных контура: подготовку данных (Python) и фронтенд-визуализацию (HTML/JS).

## 1. Подготовка данных (`preprocessing.py`)
1. **Загрузка исходников**: через `kagglehub.dataset_download` подтягивается свежий CSV WTA и выбирается самый крупный файл.
2. **Приведение типов**: колонка `Date` переводится в `datetime`, числовые поля конвертируются в числа.
3. **Фильтрация**: удаляются строки без даты, с отрицательными очками, а также матчи, в которых `Winner` не совпадает с `Player_1`/`Player_2`.
4. **Целевая переменная**: создаётся `y = 1`, если победил фаворит (`Player_1`), иначе `0`.
5. **Дубли/зеркала**: удаляются дубликаты по сочетанию `Date`/`Tournament`/`Round`/`Player_1`/`Player_2`.
6. **Нормализация фаворита**: при необходимости свапаются колонки игроков, чтобы `Player_1` всегда был фаворитом (сильнее по рейтингу/коэффициенту), после чего `y` пересчитывается.
7. **Базовые признаки**: добавляются `year`, разницы рейтингов/очков/коэффициентов (`rank_diff`, `pts_diff`, `odd_diff`).
8. **Очные встречи**: для каждой пары считается текущее преимущество (`h2h_advantage`) и последний победитель (`last_winner`).
9. **Поверхность**: накапливается индивидуальный винрейт по покрытию и сохраняется разница винрейтов `surface_winrate_adv`.
10. **Сохранение**: итоговый датасет сохраняется в `wta_data.csv` только с модельно полезными колонками.

## 2. Загрузка и обработка на фронтенде (`charts.js`)
1. **Инициализация**: при `DOMContentLoaded` вызывается `init`, который привязывает переключатель режима (WTA/ATP) и загружает датасет выбранного режима.
2. **Парсинг CSV**: `Papa.parse` загружает матчи (`wta_data.csv` или `atp_data.csv`), после чего данные проходят доп. обработку `ensureFeatureEngineering` для заполнения ключевых признаков, если они отсутствуют.
3. **Возраст игрока**: подгружается карта дат рождения (`player_age_wta.csv`/`player_age_atp.csv`), принимающая форматы `dd.mm.yyyy`, затем для каждой строки рассчитывается точный возраст на дату матча (`computeAgeOnDate`) и группа возраста.
4. **Формовые метрики**: вычисляются скользящие винрейты (5/10 матчей), текущие серии побед/поражений, усталость (число матчей за 7/14/30 дней) и тренд по покрытию.
5. **Сбор сводок**: определяется набор числовых колонок, собирается статистика пропусков, корреляций и качества признаков.
6. **Инициализация UI**: формируются кнопки выбора признаков, таблица качества, списки игроков и запускаются рендеры всех графиков.

## 3. Основные визуализации (`index.html` + `charts.js`)
- **Обзор**: блок с количеством строк, диапазоном лет, средним возрастом и списком числовых признаков.
- **Пропуски**: столбчатая диаграмма доли пропусков по столбцам.
- **Распределения**: гистограмма для выбранного числового признака.
- **Корреляции**: тепловая матрица корреляций обязательных признаков.
- **Качество признаков**: таблица и барчарт по вариативности/пропускам.
- **Игроки**: топ по победам, винрейты, матчи по покрытиям, тренд по годам.
- **Таймлайны игрока**: скользящий винрейт, профиль возраста, серии побед/поражений, усталость и тренды по покрытию (все используют выбранного игрока).

## 4. Экспорт данных
Кнопка «Download CSV» генерирует фильтрованный датасет для моделирования, ограничивая выгрузку списком колонок `MODEL_EXPORT_COLUMNS` и сохраняя текущий режим (WTA/ATP).
